# 聊天室／私訊 UI 回歸流程

## 自動驗證

在專案根目錄執行 `powershell -NoProfile -File docs/test-twitch-ui.ps1`。
此流程只執行三組指定測試，不清除帳號、cookie、App 設定或私訊，也不自動執行 analyze。

- 共用面板：搜尋、關閉、垂直分類、80px 短高度、緊密 Wrap、原生動圖元件路由。
- 聊天室：實際內嵌共用面板、底部空白、鍵盤／短畫面與操作權限。
- 私訊：桌面／手機／短橫版、輸入列中心對齊、表情與 Twitch 貼圖切換、草稿插入與額度。
- 初次開啟：最新訊息從第一個畫面位於底部；同步完成不產生程式捲動。
- 閱讀舊訊息：歷史補載保留同一訊息的可視位置；新收件不搶走閱讀位置。只有手動「返回最新」會移動。
- 鍵盤縮放：在歷史中間閱讀時保留捲動位置；最舊邊界因視窗變大可能合法縮限，不要求無效的舊 offset。
- 正常流程不顯示收件連線、同步成功說明、固定額度提示或重新整理按鈕；真實授權、儲存、同步錯誤仍可查看／重試。

## 捲動實作

私訊使用反向 CustomScrollView，offset 0 就是進入時的最新位置。
中心以開啟時的最後訊息 ID 固定：舊歷史向上增加，新訊息向下增加。
開啟與歷史同步都不再排程跳到底部；不使用一連串 post-frame 修正來掩蓋首次位置錯誤。
私訊仍只使用自身可用官方貼圖資料，未修改 GQL hash、token 儲存或發送協議。

## 實機仍需測試

1. Windows 進入私訊：第一眼就看見最新訊息，等待同步後不再上下跳；滑鼠滾輪往上閱讀不被新訊息拉回。
2. Android 開啟／關閉鍵盤，轉直／橫向，在歷史中間及最舊邊界檢查閱讀位置。寬度變化造成文字換行，應看訊息位置，不只看數字 offset。
3. 聊天室及私訊打開貼圖：輸入框在面板上方、分類在左側、底部沒有大片黑色空白；搜尋、切換及關閉可操作。
4. 私訊第一次同步無本機歷史、已有本機歷史、切換對話、新訊息到達及補載多頁，都不能強制動畫拉到底部。
5. 靜態／GIF／WebP 貼圖實際播放、輸入與傳送後顯示。Widget 測試只證明原生元件路由，不證明平台解碼或 Twitch 真實網路成功。
6. 真實同步失敗時，錯誤仍可找到；沒有清空舊資料、重複訊息或洩漏帳號憑證。

本流程尚未建立截圖 golden 基準，不能以自動測試通過宣稱視覺設計已經實機確認。
