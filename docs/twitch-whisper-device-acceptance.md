# 私訊最終真人／裝置驗收

狀態：尚未執行。本機 mock 回歸不能代替以下驗收。只使用測試者自己控制或同意參與的帳號；代理不代為向真人發私訊，不封鎖或清除聊天室。結果需分別記錄 Windows 與 Android、App 版本及時間；不要貼 token、cookie、私人訊息全文。

## 授權與帳號隔離

主登入失效但另一個Web/Drops帳號仍留存時，私訊session應停止，不改載入另一人的對話；原owner草稿保留。主登入已換成另一人時，舊owner的既有發送也不得借舊Webtoken繼續。以上有API/controller mock，真人還未測，代理不代發驗證。

1. 在私訊列表選單使用「授權並重試對話同步」。Windows 應使用既有獨立 WebView 視窗；Android 使用既有 Flutter 內嵌 WebView。應取得主帳號私訊 scope 與同帳號 Web 授權，不要求 Drops 才能返回私訊。一般完整登入仍有自己的 Drops 流程。
2. 成功後確認列表有本機從未建立過、但 Twitch 已有的對話。不出現 `currentUser:null`／GraphQL 錯誤才是已登入列表 API 的成功證據。資料不可見不當作成功或空清單。
3. 分別取消授權、使用錯誤 Web 帳號、授權中關閉面板：原草稿與對話不清空，不自動對另一帳號同步。不應把主 OAuth 或 Drops token 借作 Web token。
4. 換 App 主帳號後確認舊帳號私訊不顯示、不通知新帳號；再切回確認舊草稿與歷史仍在。同步等待期間換帳號也不能合併晚頁。

   額外檢查登入前 Home 已在刷新、授權後換帳號的情況：私訊面板需等待原刷新後再驗證新憑證，不可立即用舊 owner 重試；此情況已有 mock，真人平台仍未測。

## 遠端列表與本機恢復

5. 對話超過一頁時「載入更多對話」應取得後續未知對象；重開 App 後仍能續接。明確「同步 Twitch 對話」重新從第一頁刷新。沒有後續頁時停止；失敗不能推進 cursor。

   刻意斷網或等待逾時後，按「重試對話同步」应讀同一失敗分頁，不退回第一頁；網路等待時按取消，原資料保留，後續晚回應不推進進度。commit開始後取消入口應消失。現在只對列表遠端讀取套用45秒逾時；單一對話歷史不在本輪範圍。沒有保證底層HTTP已中止。
6. 對話內「同步近期歷史／載入更早訊息」應有雙向訊息；原本草稿、本機未讀及閱讀位置不因歷史同步被清除。資料只有歷史時不發即時通知。

   單一對話歷史也加入45秒待讀逾時、選單取消／重試。驗證更早頁失敗後重試原cursor、待讀時換peer或帳號不附錯頁、取消後晚回應不動原進度。保存開始後不可取消，底層網路未保證中止。本段為最新範圍，取代上一段較早的「歷史未納入」紀錄；真人仍未測。

   在某則可見訊息停住，連續載入三頁較早資料（含多行/貼圖），確認同一訊息在閱讀區內仍停在原位置，且可向上捲動找到新增頁；再測鍵盤開關及大字級。桌面/手機等高/變高 mock 已驗證相對 viewport anchor，但真人／字級與鍵盤prepend組合尚未測。
7. 本機 badge 與「Twitch 未讀（上次同步）」是不同來源。選取本機對話可以清本機未讀，但不宣稱 Twitch 網站已標讀；遠端數字直到下次同步才刷新。

## 真正收发及背景

8. 由真人測試者手動在兩個同意測試的帳號間收發。發送成功僅表示 Twitch 接受，不宣稱對方已讀／送達。觀察時間、名字、徽章／貼圖及訊息內容是否正確；目前代理只做 mock，不觸發真實發送。
9. 關閉私訊面板但保持 App 執行、再開其他觀看頁，確認同一背景收件仍處理未讀／通知與對象入口；同 ID 重送不多算。App 完全退出後的伺服器訊息需靠遠端同步恢復，不能宣稱已常駐收件。
10. 面板正在讀尾端、正在看舊訊息、App 到背景各測一次。不要因捲動估計而提前清未讀。Android 是否可在作業系統限制下維持連線需實測，不以桌面測試推論。
11. 同步列表／歷史時讓另一測試帳號手動送新訊息，並修改草稿。即時先到與歷史先到都不應漏首次 live 收件；重開後不能重复通知或覆寫草稿。

2026-10-04待存確認驗收補充（真人／實機未測）：已存缺口後換帳號再切回，新會話碼不得被原已存事件重播覆蓋，原恢復工作仍需重新列舉，草稿保留。快速兩次信號且第一項仍保存時，第一完成不得清掉第二待存；提交開始後換owner，寫入只屬原owner，新owner不顯示其對話，切回亦不重播已确认舊碼。取消與磁碟故障維持待存，但退出未存資料仍無保證；只用可丟棄測試環境，不延遲／破壞使用者真人資料。

背景收件保存故障補充（未實機測）：在可丟棄的測試環境中，確認已收到但無法保存的私訊提示「暫存於記憶體／退出可能遺失」；恢復後重新載入可補存，重複官方ID不重複未讀/通知，換帳號不顯示原owner事件。已保存但通知失敗應不阻擋後續收件。clearSession/退出會丟暫存而不清磁碟；容量滿的拒收事件需遠端歷史恢復，無完整補齊保證。此機制不涵蓋EventSub斷線未收到App的事件，仍需獨立驗證。代理只有mock，未用真人事件或破壞真實資料測試。
