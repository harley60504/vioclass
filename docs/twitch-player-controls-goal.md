# 播放器控制改善目標

## 範圍與驗收

1. 純直播暫停後按播放，重新接到直播端；DVR、VOD、剪輯保留原觀看位置。
2. 播放器控制列提供設定入口與倍速；沿用原有播放、手勢、影像及音訊設定，不新增第二套偏好。
3. 畫質與音量浮層以按鈕為錨點，優先向上展開；靠近上緣時可向下，窄視窗內保持可操作。
4. 最高畫質選擇可用的最高影片規格，不選到純音訊。自動模式會在持續卡頓時降級、穩定後逐級升級，並有冷卻時間；手動畫質不被自動改動。
5. Flutter widget／controller 測試與 Windows 原生播放器受控測試；不控制系統滑鼠，不改登入、IRC、GQL hash 或平台專用檔案。

## 參考

- [StreamNook VideoPlayer](https://github.com/StreamNook/StreamNook/blob/main/src/components/VideoPlayer.tsx)：畫質選單區分自動模式與當下實際畫質。VioClass 依自身播放器架構實作，不直接搬用其程式。

## 狀態

本輪實作與有界驗收已完成，納入 2.0.9 發布。

- 純直播按播放會走重新接流／重開原生來源；DVR、VOD、剪輯仍走原本播放位置。
- 右側播放器設定改為播放區內滑出的抽屜，不使用獨立對話框，不覆蓋或封鎖聊天室；沿用原有偏好面板。0.5～2× 的本次播放倍速移至畫質按鈕的快速選單。
- 畫質浮層與音量浮層皆錨定在按鈕上方，必要時翻向下方；窄版位置測試通過。
- 最高／自動／手動模式會保存選擇。自動採卡頓回饋調整（不是頻寬估算）：連續緩衝 6 秒降一級，穩定 60 秒升一級，切換後至少冷卻 30 秒。相同規格的替代來源不當作不同級別，純音訊不參與排名。
- 暫停、DVR、切換來源中與隱藏觀看路由時不自動切換；迷你播放器不另啟動第二個自動調整器。
- 54 項控制／設定／手勢／畫質測試，以及 17 項原有觀看流程回歸通過。
- Windows 原生播放器測試確認暫停直播後重新開流、mpv 實際套用 1.5×、背景恢復與 DVR 保留位置；未操作系統滑鼠。
- 後續介面與配色調整的單次 flutter analyze 均無問題。真實 Twitch 長時間網路波動與 Android 實機體驗尚未觀察，不宣稱已完成這些實測。
