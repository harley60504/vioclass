# Android 背景通知與移除工作

## 行為

- 開台通知：WorkManager 唯一週期工作 `vioclass_followed_live`，15 分鐘間隔並要求網路。省電模式可延後，並非即時推播。
- Android 不再同時跑原先 Flutter 開台輪詢，避免重複通知；Windows 原輪詢不變。
- 背景收件服務運作時，另在同一服務的單一背景執行緒約每分鐘檢查開台（上一輪結束後間隔 60 秒）；不新增服務或常駐通知。服務停止時取消快速檢查，保留系統週期排程。
- 快速檢查與 WorkManager 使用同一份原生快照、帳號版本檢查及互斥閘門，避免重疊查詢和重複通知；關閉開台通知或登出後不再查詢。私訊維持事件連線即時收件，不另加輪詢。
- 原生公開快照包含直播卡片所需的分類、人數、縮圖與頭像，追隨頁及側欄經 `followedLiveSnapshot` 讀取同一份結果。快照新鮮時不重查；同時請求等待既有檢查完成，超時或未配置時才回到既有登入 API。
- Flutter 的相同追隨直播分頁在一分鐘內共用結果與進行中的請求；電腦通知、追隨頁及側欄均走此入口。帳號／token 改變與明確清除快取會隔離舊結果；原生橋接只傳 owner ID 與公開直播資料，不傳 token 或 cookie。
- 原生完整快照的 UI 分頁固定在同一份資料上，避免翻頁期間名單變動造成重複／漏項；開台開關關閉、原生未就緒或查詢失敗時，畫面保留既有登入 API 路徑，不強制開啟通知。
- 共用快照驗證：74 項 Flutter 回歸與原生單元測試通過。2026-10-20 覆蓋安裝至 SM-X510 後，原生成功檢查 126 頻道、取得 32 個直播，並記錄 `snapshot delivered=true`；背景服務仍存活。未清除登入資料，未讀取通知或私訊內容。
- 開啟 App／帳號同步時取得完整追隨清單，只將帳號識別碼、公開頻道名稱與公開 Client-ID 交給原生排程。不複製登入 token、refresh token 或 cookie，也不修改原本登入儲存邏輯。
- 背景工作查 Twitch 公開直播資料；初次快照靜默建立基準，之後只通知離線轉直播。查詢失敗／不完整資料不更新基準；登出、切換帳號與關閉開關會取消舊工作，延遲回應不得通知舊帳號。
- 新追隨／取消追隨需要重新同步清單；背景工作不會在 App 關閉時更新私人追隨清單。Twitch 公開端點仍可能受上游變動影響。
- 私訊：使用既有 EventSub 接收器，不建立第二條收件連線。啟用後由原生前景服務持有 wake lock，移除工作不停止；Flutter engine 在 Activity 銷毀後保留，再開啟時重用同一個 engine。
- `flutter_background` 僅用於既有電池最佳化授權流程，不啟動其會在 `onTaskRemoved` 停止的原服務。
- 關閉私訊常駐收件／登出會停止服務。沒有 Activity 時服務停止也會釋放保留的 engine；有 Activity 時不銷毀畫面所需的 engine。
- App 被系統強制停止後不繞過系統限制。若廠商省電回收整個程序，私訊服務不盲目重啟沒有授權接收器的空服務，須重開 App；開台排程仍由系統管理。重開機後私訊也須重新開 App。
- 通知權限拒絕時顯示提醒與系統設定入口；只在使用者啟用功能時要求通知／背景權限，正常恢復不重複跳授權。

## 有界驗收

1. Flutter 測試涵蓋權限拒絕／查詢失敗、設定跳轉、背景授權、完整追隨分頁、登出時忽略舊回應、開關及非 Android 不調用原生功能。
2. Kotlin 單元測試涵蓋靜默基準、離線轉直播及公開查詢名稱過濾。
3. Android instrumentation 以測試服務驗證移除工作後 engine／服務仍在、重開重用 engine、明確停止後釋放；不發真實私訊。
4. WorkManager instrumentation 驗證不依賴 Flutter 畫面即可建立／取消排程。
5. 平板實際收件仍須登入後由另一帳號發私訊，並以至少一輪 15 分鐘開台檢查觀察通知；模擬器生命週期測試不能代替這項實收驗收。

## 開台通知 HTTP 400 修正

- 平板實測顯示工作確實執行，但在 HTTP 階段收到 400 後反覆 RETRY，指數退避拉長到兩小時級別；不是全域通知權限未允許。
- 最小公開對照確認 Twitch 拒絕 25 個根欄位 alias，回應上限為 15。工作改成每批最多 15 頻道；126 頻道的回歸案例須完整拆成 9 批。
- 修正後平板完整檢查 126 頻道、取得 19 個直播，WorkManager 回報 SUCCESS，下一輪恢復約 15 分鐘排程。該次為初次成功建立基準，沒有將既有直播當成新開台通知。
- 同帳號重開時，準備同步追隨清單不再先以空清單清掉已保存的基準；真正登出、換帳號或完整空追隨清單仍會取消舊工作。
- 增加本機診斷紀錄：階段、HTTP 狀態、例外型別與數量；不記錄 token、cookie、訊息內容或追隨清單。HTTP 錯誤文字會遮蔽本批頻道名稱並截短。
- 真實新開台事件到系統通知的最後一步，仍須有後續新開台事件才可驗收；單次查詢成功不等同這一步已驗證。
